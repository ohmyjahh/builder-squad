# Quality Gate — Completude do Intake

## Classificação obrigatória

- [ ] A finalidade é `internal`, `market` ou `hybrid`.
- [ ] A finalidade foi confirmada pelo usuário.
- [ ] O tipo de projeto foi identificado.
- [ ] O contexto de entrega foi identificado.

## Resultado e usuários

- [ ] Existe resultado observável.
- [ ] Existe critério inicial de sucesso.
- [ ] Usuário, beneficiário, pagador e aprovador estão diferenciados quando aplicável.
- [ ] A situação atual foi registrada.

## Complexidade

- [ ] Interface foi classificada.
- [ ] Persistência de dados foi classificada.
- [ ] Backend foi classificado.
- [ ] IA/agentes foram classificados.
- [ ] Integrações foram classificadas.
- [ ] Pagamentos foram classificados.
- [ ] Complexidade possui score e justificativa.

## Risco

- [ ] Dados sensíveis foram verificados.
- [ ] Criticidade operacional foi verificada.
- [ ] Ações externas ou autônomas foram verificadas.
- [ ] Produção pública foi verificada.
- [ ] Autoridade para aprovações foi definida.

## Específico: internal

- [ ] Dono do processo identificado.
- [ ] Baseline disponível ou plano para medi-lo.
- [ ] Continuidade operacional considerada.
- [ ] Usuários afetados e adoção considerados.

## Específico: market

- [ ] Problema e segmento explicitados.
- [ ] Evidência existente ou discovery obrigatório.
- [ ] Pagador e usuário diferenciados.
- [ ] Hipótese de monetização registrada.
- [ ] Aquisição e suporte considerados.

## Específico: hybrid

- [ ] Benefício interno imediato definido.
- [ ] Intenção futura de mercado registrada como hipótese.
- [ ] Tenancy, separação de dados e licença entram na rota.

## Veredito

- **PASS:** todos os itens aplicáveis atendidos.
- **CONCERNS:** lacuna não crítica aceita e registrada.
- **FAIL:** finalidade, resultado, usuário ou risco crítico ausente.
- **BLOCKED:** depende de informação ou autoridade externa.
